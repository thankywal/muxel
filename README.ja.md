# Muxel

セルフホスト型の AI サポート担当です。ご自身の価格表やポリシーをもとに Telegram
でお客様に返信し、すべてはご自身の Cloudflare アカウントの中だけで動きます。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel)

はじめての方は、まず [始める前に](#始める前に) をお読みください。無料のアカウントが
4 つと 10 分ほどの時間が必要で、そのうち 2 つは deploy のフォームで入力します。

Muxel のサーバーも、Muxel のデータベースも、Muxel のアカウントもありません。書類も、
会話も、認証情報も、お客様が管理する環境の外に出ることはありません。

## できること

* すべてボタンだけで操作できるコンソール bot があります。セットアップのあとは
  dashboard も設定ファイルも必要ありません。
* お店ごとにお客様用の bot があり、アップロードした価格表、ポリシー、商品情報を
  もとに返信します。
* 返信は必ず書類にもとづきます。アシスタントは答えを作り出すのではなく書類の内容を
  引用し、わからないときははっきりとそう伝えます。
* 相手が誰かを覚えています。会話から確かな事実を取り出して残すので、再びご来店の
  お客様が同じ説明を繰り返す必要はありません。
* お客様の一覧には、進み具合、メモ、そして本当に消える削除があります。
* 指示はご自身で書きます。コンソールからテキストまたは markdown ファイルで
  差し替えられ、変更でかえって悪くなったときは元に戻せます。
* 1 つの deploy でお店をいくつでも運用でき、それぞれは互いに切り離されています。

## 始める前に

必要なものは 4 つ、どれも無料で、時間は 10 分ほどです。どれもクレジットカードを
求めませんし、コードを書く場面もいっさいありません。

### 1. Cloudflare アカウント

Muxel が動く場所であり、書類と会話が保管されるアカウントです。
[dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) で登録し、
届いたメールで確認してください。無料プランのままで大丈夫です。Muxel はカードを
求める機能をあえて使っていないので、カードの入力を求められることはありません。

すでにアカウントをお持ちの方は、サインインして次に進んでください。

### 2. GitHub アカウント

Cloudflare はこのコードの写しをお客様ご自身の名義で保管します。更新したときに
アシスタントを作り直せるようにするためです。
[github.com/signup](https://github.com/signup) で登録してください。

そこで何かを書く必要はありません。セットアップが終われば閉じて忘れてしまって
構いません。あとで説明する 1 つの設定だけは別です。

### 3. Telegram の bot を 2 つ

Telegram で [@BotFather](https://t.me/BotFather) を開き、`/newbot` を送ってください。
これを 2 回行います。2 つの bot は役割が違い、同じものであってはならないからです。

| bot            | 話しかける人 | 名前の例         |
| -------------- | ------------ | ---------------- |
| コンソール bot | あなただけ   | My Muxel Console |
| お店の bot     | お客様       | お店の名前       |

お客様に見えるのはお店の bot の名前なので、そちらにはお店の名前を付けてください。
BotFather は `/newbot` ごとに `8012345678:AAH...` のような長い token を返します。
どちらもコピーできる場所に控えておいてください。

deploy に必要なのはコンソール bot の token だけです。お店の bot の token は、
あとでコンソールの中で尋ねられます。

### 4. あなたの Telegram アカウント ID

[@userinfobot](https://t.me/userinfobot) に `/start` を送ってください。数字が
返ってきます。コンソールはこの数字で、bot を見つけたほかの誰かとあなたを区別します。
ほかの人が操作することはできません。

## ブラウザから deploy する

ボタンを押すか、次のリンクをブラウザに貼り付けてください。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel)

```
https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel
```

フォームが表示される前に、Cloudflare は 3 つのことを尋ねます。まだサインインして
いなければサインイン、GitHub アカウントの接続、そしてそこへの Cloudflare の GitHub
アプリのインストールです。これは承認してください。Cloudflare がコードの写しを作り、
更新のたびに作り直すための仕組みです。

以前のプロジェクトから **Cloudflare Workers and Pages** というアプリが GitHub
アカウントに残っている場合は、先に
[github.com/settings/installations](https://github.com/settings/installations)
で削除し、この流れで現行のアプリを入れ直してください。古いアプリはリポジトリを
不完全に写すことがあり、その場合デプロイは成功と表示されるのに何も動きません。
対処は [docs/DEPLOY-RECOVERY.md](docs/DEPLOY-RECOVERY.md) にあります。

フォームでは、KV の名前空間と D1 データベースについては提案された名前をそのまま
受け入れ、4 つの項目を入力します。

**Vectorize のインデックスでは、こちらでは埋められない値を 2 つ尋ねられます。**
インデックスを作るときに決まる値で、Worker の設定にはどちらの項目もないため、
入力欄は空のまま表示されます。

| Vectorize の項目 | 値       |
| ---------------- | -------- |
| 次元数           | `1024`   |
| 距離の指標       | `cosine` |

間違えても、もう致命的ではありません。埋め込みはインデックスが作られた設定に
合わせられ、セットアップ画面がその影響を教えてくれます。大きすぎる数値は場所を
無駄にするだけで、動きは変わりません。ゼロで埋めてもコサイン類似度はそのままだから
です。小さすぎる数値は埋め込みを縮めて合わせるので、検索の精度が下がります。直した
ほうがよいものの、それで動かなくなるわけではありません。

続いて 2 つのシークレットです。

| 設定                | 値                                                 |
| ------------------- | -------------------------------------------------- |
| `ADMIN_BOT_TOKEN`   | BotFather で作ったコンソール bot の token          |
| `OWNER_TELEGRAM_ID` | @userinfobot が返したあなたの数字、数字のみ        |

これ以外は Telegram の webhook も含めて自動で用意されます。deploy の段階で Worker
に最初のリクエストが送られ、Worker が自分のアドレスを知る仕組みです。

ビルドが終わったら、コンソール bot を開いて `/start` を送ってください。その bot が
あなた専用の操作画面です。そこでお店を追加すると、お客様が話しかける bot を
尋ねられます。

bot が黙ったままのときは、Cloudflare が表示した Worker のアドレスを開いてください。
そのページがセットアップをもう一度実行し、どこが問題かを教えてくれます。

**そのアドレスが `Hello world` と答える場合、デプロイは完了していません。**
Cloudflare はビルドの前にこのリポジトリをあなたの GitHub アカウントへ写しますが、
その写しがまれに失敗し、それでもダッシュボードは成功と表示します。Muxel は一切
動いていないため、問題をあなたに知らせるものも存在しません。確認方法と、GitHub を
まったく使わないものを含む 2 通りの導入方法を
[docs/DEPLOY-RECOVERY.md](docs/DEPLOY-RECOVERY.md) に書いてあります。

<details>
<summary>deploy のあとは、写しを非公開にしてください</summary>

Cloudflare はこのリポジトリをお客様の GitHub アカウントに複製します。その写しは
**公開**の状態で作られます。

お店のデータがそこに入ることはありません。書類、会話、お客様の記録は D1 と
Vectorize にあり、Worker が git に書き込む手段はありません。シークレットも
書き込まれません。Worker のシークレットとして保管され、`.dev.vars` は無視されます。

写しに入るのは、deploy のときに `wrangler.jsonc` へ書き込まれる、アカウント内の
リソースの識別子です。これは認証情報ではなく、アカウントがなければ何かを読み取る
こともできませんが、公開しておく意味はありません。Settings、General、
Change visibility からリポジトリを非公開にしてください。

セットアップのページがこれを確認し、写しが公開のあいだはその設定への直接のリンクを
表示します。対応すれば知らせは消えるので、覚えておくことも、閉じる操作も必要
ありません。Muxel 自身がこの変更を行うことはできません。リポジトリは Cloudflare の
GitHub アプリが作るものであり、写しには `.github` ディレクトリが含まれないため
こちらのワークフローは動かせず、Worker は GitHub の認証情報を持っておらず、持つべき
でもないからです。

そのあともビルドは動き続けます。Cloudflare は、許可したリポジトリに対して
`contents: write` を持つインストール済みの GitHub アプリとしてリポジトリに
アクセスします。インストールの権限は、リポジトリが公開かどうかに左右されません。

公開のままである必要があるのは、ボタンを配信しているリポジトリだけです。それはこの
リポジトリであり、お客様の写しではありません。

</details>

## 最新の状態を保つ

更新は自動では**ありません**。その理由をはっきりさせておきます。

deploy ボタンは GitHub の fork ではなく独立した写しを作ります。そのため Sync fork の
ボタンはなく、写しとこちらを結び付けるものもありません。また、取り込みの仕組みが
ワークフローのファイルを作れないため、**`.github` ディレクトリを除いて**複製され
ます。このリポジトリに入っている更新用のワークフローは、お客様の写しには届きません。

自動で行われることもあります。お客様の deploy はこのリポジトリに新しい版がないかを
確認し、あればバージョンごとに 1 回、**コンソール bot でお知らせします**。自分で
見に行くことを覚えておく必要はありません。

### 更新を適用する

```bash
git clone https://github.com/<you>/muxel.git && cd muxel
git remote add upstream https://github.com/thankywal/muxel.git

# every time, from here on
git fetch upstream
git checkout upstream/main -- .
git checkout HEAD -- wrangler.jsonc      # keeps your resource identifiers
git commit -am "Update from upstream" && git push
```

push すると Workers Builds が動き、再 deploy とセットアップの仕上げが行われます。
データ、設定、bot はそのままです。

### 自動にする

手作業を 1 回だけ行えば、そのあとは毎日自動で更新されます。GitHub 上の写しで
**Add file**、続いて **Create new file** を選び、`.github/workflows/update.yml` と
いう名前にして、[このリポジトリのワークフロー](.github/workflows/update.yml) を
貼り付けてください。取り込みの仕組みでは作れなくても、手作業ならワークフローの
ファイルを作れます。

そのあと **Settings**、**Actions**、**General**、**Workflow permissions** が
*Read and write* になっているか確認してください。そうでないと、この処理はご自身の
リポジトリに push できません。

更新が適用されるのは、上流のコミット自身のテストが通っている場合だけです。壊れた
コミットが、目の届かないところで営業中のお店に届くことはありません。Actions の
タブから **Run workflow** で、必要なときに手動で実行することもできます。

写しは上流に追従するため、履歴は統合ではなく置き換えられ、手元でのコードの変更は
残りません。設定はコンソールから行ってください。コードを変更するつもりがある方は、
このワークフローを追加しないでください。

## ターミナルから deploy する

この節は開発者向けの内容のため、[英語版の README](https://github.com/thankywal/muxel#deploy-from-a-terminal) にそのまま残しています。

## モデルを選ぶ

お店ごとにモデルの名前が保存されます。変更はコンソールでボタンを押すだけで、
再 deploy は必要ありません。

| モデル            | 返信 1,000 件あたりの費用 | プロバイダーのキーが必要か |
| ----------------- | ------------------------- | -------------------------- |
| Gemma 4 26B       | 約 0.33 米セント          | 不要                       |
| Llama 3.3 70B     | 約 0.86 米セント          | 不要                       |
| GPT-5.6 Luna      | 約 0.76 米セント          | 必要                       |
| Claude Sonnet 4.5 | 場合によります            | 必要                       |

Cloudflare のログインで届くのは Workers AI のモデルだけです。ほかのプロバイダーを
選ぶには、まず AI Gateway にキーを保存しておく必要があります。そのためコンソールは
そうしたモデルに印を付け、最初のお客様のメッセージで失敗するモデルを選んでしまわない
ようにしています。

既定は Gemma 4 です。検索にもとづく返信で計測すると、1,000 件あたり 1 米セントの
3 分の 1 ほどで、1 日およそ 330 件までが無料の 1 日枠に収まります。埋め込みには
常に `bge-m3` を使います。多言語に対応していて、実質無料です。

## bot は 2 種類あります

この違いは大切で、コンソールもその違いを軸に作られています。

| | コンソール bot | お店の bot |
| --- | --- | --- |
| 話しかける人 | あなただけ | お客様 |
| 届く範囲 | すべてのお店 | 1 つのお店だけ |
| どこから来るか | deploy 時の `ADMIN_BOT_TOKEN` | コンソールでお店ごとに作成 |
| お店に属するか | 属しません | はい、担当するお店に |

お店は、それを担当する bot があるからこそ存在します。ですから 2 つは一緒に作られ
ます。お店の追加では名前ではなく bot の token を尋ね、bot 自身の名前がお店の名前に
なります。お店だけが先にできて bot を待つことはありませんし、コンソール bot をお店に
結び付けることもできません。コンソールは自分自身の token を受け付けないからです。

## コンソール

セットアップのあとは、すべてコンソール bot の中で、ボタンを押して行います。

| 画面 | 内容 |
| --- | --- |
| データ | アップロードしたファイル。1 件ずつ並び、どれにも削除が付いています |
| 商品 | 1 件ずつ入力するか、まとめてアップロードした品目 |
| お客様 | 書き込みのあったすべての方。進み具合、メモ、記憶が付きます |
| 指示 | アシスタントに対するご自身のルール。元に戻す操作が付きます |
| bot | お客様が話しかけるお店の bot と、その追加 |

データでは PDF、Word、Excel、CSV、TXT、Markdown、JSON、JSONL を受け付けます。
テキスト形式はそのまま読み取ります。表計算や文書のファイルはプラットフォームの
変換機能を通し、読み取れなかった PDF はテキスト層に対してもう一度試します。Excel
から書き出した価格表が使えるのは、このためです。

ファイルは必ずどれかのお店に属します。そのためコンソールは推測せず、アップロードを
受け付ける前にお店を開くようお願いします。

商品がファイルとは別にあるのは、ファイルは丸ごとしか差し替えられないからです。価格が
1 つ変わるたびにカタログを上げ直すことになってはいけません。商品は
`name | price | description` の形で 1 行に 1 件ずつ入力するかアップロードし、1 件
ずつ削除できます。変更のたびに、アシスタントが知っている内容が作り直されます。

お店を削除するときは確認を求め、そのうえでファイル、商品、お客様、bot、ベクトルを
まとめて消します。

### 言語

コンソールは English、ไทย、中文、မြန်မာ に対応しています。言語は操作する人ごとの
設定で、次の画面だけでなくすべてのボタンが変わります。お店がお客様に返信する言語とは
別のものです。

## アシスタントが答えるべきでないとき

アシスタントは、渡された書類にもとづいて答えます。書類にない質問もあります。誰も
書き残していない値引き、苦情、特別な注文などです。そうしたことを推測で答えるのは、
お客様を失う失敗です。ですからアシスタントは推測しません。

代わりに、担当者があらためて連絡することをお客様に伝え、あなたにも知らせます。
知らせはコンソールに届き、その会話を開くボタンが付いています。

コンソールのお客様の画面からできることです。

| 操作                            | 起きること                                                     |
| ------------------------------- | -------------------------------------------------------------- |
| **会話**                        | やり取りの全文が、どちらの発言かの印付きで表示されます          |
| **引き継ぐ**                    | そのチャットでアシスタントが黙ります                            |
| **メッセージを送る**            | あなたが入力し、お客様はお店の bot から受け取ります             |
| **アシスタントに戻す**          | アシスタントが返信を再開します                                  |

あなたが対応しているあいだ、アシスタントは前に出ずに、お客様が書いた内容をそのまま
転送します。同じ相手に 2 つの声が返信することはありません。あなたが送ったメッセージ
は会話の一部として記録されるので、チャットを戻したときには、アシスタントもその内容を
読んだ状態になっています。

コンソールのホームにある **人の対応待ち** には、あなたの対応が必要なチャットが、
すべてのお店にわたって並びます。

アシスタントが答えられない質問が 1 つあっても、そのチャットの残りで黙ってしまう
わけではありません。ほかのことには答え続けます。難しい質問が 1 つあっただけで
黙り込むほうが、その質問よりも困ることになるからです。

## 指示と書類は別のものです

アシスタントはこの 2 つを違う信頼度で扱う必要があるため、コンソールでも分けています。

| | 指示 | 書類 |
| --- | --- | --- |
| 書く人 | あなた | あなた。ただし仕入先やお客様から来たものも多い |
| 扱い方 | アシスタントが従うルール | 引用してよい事実 |
| 置かれる場所 | システムプロンプト | 引用の区切りの中 |

指示はあなた自身の文章なので、話し方や方針を決めます。書類は信頼できない入力なので、
アシスタントにはあらかじめ、それをデータとして読むように伝えてあります。PDF の中の
一文がアシスタントの振る舞いを変えることはできませんし、価格を作り出さないという
ルールは、指示に何が書かれていても残ります。

書類はいつでもコンソールに送れて、最後に開いていたお店の知識に加わります。指示は
指示の画面から、メッセージまたは `.md` ファイルではっきりと差し替えます。ひとつ前の
版が残るので、よくない変更は元に戻せます。

## 記憶

お客様についての事実は、数メッセージごとに会話から取り出され、その方の記録に
保存されます。再びご来店のお客様が、何を買ったか、どう支払うかを言い直す必要は
ありません。

事実は D1 に保存され、埋め込んで検索するのではなくキーで読み出します。1 人に貯まる
事実は数千ではなく数十なので、索引を使った 1 回の問い合わせですべて取り出せます。
おかげで Vectorize の枠はすべて書類に使えます。意味での検索が費用に見合うのは、
書類のほうだからです。

お客様の画面には覚えている内容が表示され、事実を忘れさせることも、その方の記録ごと
削除することもできます。

## コンソール bot を変更する

コンソールで bot を開き、コンソール bot の差し替えを選んで、新しい token を送って
ください。先に古い bot が切り離されるので、2 つが同時に返信することはありません。
新しい bot が同じチャットで確認の返事をします。

コンソールにまったく入れなくなった場合は、Cloudflare の dashboard で
`ADMIN_BOT_TOKEN` のシークレットを変更し、もう一度 `/setup` を開いてください。この
方法では webhook だけでなく、保存されている認証情報も書き換えられます。

## 運用にかかる費用

Muxel は料金をいただきません。小さなお店であれば Cloudflare の無料プランに収まります。

| リソース   | 無料枠                                | ここでの意味                       |
| ---------- | ------------------------------------- | ---------------------------------- |
| Workers AI | 1 日 10,000 ニューロン                | Gemma 4 で 1 日およそ 330 件の返信 |
| Vectorize  | 保存 5 M 次元、検索 30 M 次元         | 書類のかたまり およそ 4,800 個     |
| D1         | 5 GB、1 日 100 k 行の書き込み         | お店が出す量をはるかに上回ります   |
| Workers    | 1 日 100,000 リクエスト               | お店が出す量をはるかに上回ります   |

1 ベクトルあたり 1,024 次元とすると、Vectorize の保存枠はおよそ 4,800 個のかたまりに
あたります。価格表やポリシーで千ページほどの分量です。

推論の枠を超えた分は 1,000 ニューロンあたり 0.011 USD です。無料枠の先はプランの
変更ではなく、数セントの世界です。先にお金が必要になるのは、ほかのプロバイダーの
モデルを選ぶ場合だけで、そのプロバイダーに直接お支払いいただくことになります。

### 使った量を確認する

コンソールには **使用量** の画面があります。設定をしなくても、この deploy が今日
どれだけ返信し、それに何 token かかったかを表示します。Muxel が自分で数えている
からです。

アカウント全体の合計は別の話です。ほかの Workers も同じ枠を使うため、答えられるのは
Cloudflare だけです。表示するには、**Account Analytics: Read** だけを持つ API token
を作り、Worker の Settings、Variables and Secrets に 2 つのシークレットを追加して
ください。

| シークレット    | 値                                            |
| --------------- | --------------------------------------------- |
| `CF_ACCOUNT_ID` | dashboard の URL に含まれるアカウント ID      |
| `CF_API_TOKEN`  | いま作った読み取り専用の token                |

すると画面には、今日使ったニューロンと 1 日の枠、モデルごとの内訳、Worker の
リクエスト数、Vectorize の検索と保存、そして今日の枠であと何件返信できるかの見込みが
表示されます。この見込みは公表されている単価ではなく、実際の返信にかかった費用から
計算されるので、モデルを変えても正確なままです。

この token は読み取り専用です。deploy も、設定の変更も、データの読み取りもできません
し、Muxel が表示することもありません。

Muxel はあえて R2 のバケットを使いません。使ってもアップロードしたファイルの原本を
残すだけで、それを読み返すものはありませんし、R2 は無料の範囲でも有効化に支払い方法
が必要だからです。原本を残しておきたい場合は、`DOCUMENTS` という名前のバインディング
を追加してください。

## セキュリティ

* お店のデータが Cloudflare アカウントの外に出ることはなく、リポジトリに入ることも
  ありません。Worker が git に書き込む手段はありません。
* bot の token はデータベースに届く前に AES-GCM で封をされます。データベースの
  書き出しだけでは、使える認証情報は手に入りません。
* コンソールに貼り付けた bot の token は、すぐにチャットから削除されます。
* webhook は bot ごとのシークレットで、時間の一定な比較によって確認されます。知らない
  パスと誤ったシークレットはどちらも同じ 404 を返すので、有効な入り口を探られること
  はありません。
* 返信の処理はツールをいっさい持ちません。取り出した書類は区切られ、引用された
  データとして扱われるので、アップロードしたファイルの中の文章がアシスタントの向きを
  変えることはできません。
* お店の内容に触れる問い合わせはすべて、処理の側ではなくデータの層で、お店の識別子に
  よって絞り込まれます。

脆弱性の報告は [SECURITY.md](SECURITY.md) からお願いします。
