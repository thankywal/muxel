# Muxel

ผู้ช่วย AI ตอบลูกค้าที่คุณโฮสต์เอง ตอบคำถามลูกค้าของคุณบน Telegram โดยอ้างอิงจาก
รายการราคาและนโยบายของร้านคุณเอง และทำงานอยู่ในบัญชี Cloudflare ของคุณทั้งหมด

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel)

เพิ่งเริ่มใช้งานใช่ไหม แนะนำให้อ่าน [ก่อนเริ่มต้น](#ก่อนเริ่มต้น) ก่อน ทั้งหมดคือบัญชีฟรี
สี่อย่างและใช้เวลาราวสิบนาที และแบบฟอร์ม deploy จะขอข้อมูลสองอย่างจากในนั้น

ไม่มีเซิร์ฟเวอร์ของ Muxel ไม่มีฐานข้อมูลของ Muxel และไม่มีบัญชี Muxel เอกสารของคุณ
บทสนทนาของคุณ และข้อมูลรับรองการเข้าถึงของคุณ ไม่เคยออกไปนอกระบบที่คุณควบคุมเอง

## ทำอะไรได้บ้าง

* console bot ที่คุณสั่งงานด้วยปุ่มทั้งหมด จึงไม่ต้องเข้า dashboard และไม่ต้องแก้ไฟล์
  ตั้งค่าใด ๆ หลังจากติดตั้งเสร็จ
* bot สำหรับลูกค้าหนึ่งตัวต่อหนึ่งธุรกิจ ซึ่งตอบคำถามจากรายการราคา นโยบาย และข้อมูล
  สินค้าที่คุณอัปโหลดไว้
* คำตอบที่อ้างอิงจากเอกสารจริง ผู้ช่วยจะยกสิ่งที่เอกสารของคุณเขียนไว้มาตอบแทนการ
  แต่งคำตอบขึ้นเอง และบอกตรง ๆ เมื่อไม่รู้
* ความจำว่ากำลังคุยอยู่กับใคร ข้อเท็จจริงที่สำคัญจะถูกสกัดออกมาจากบทสนทนา ลูกค้าที่
  กลับมาอีกครั้งจึงไม่ต้องเล่าเรื่องเดิมซ้ำ
* รายชื่อลูกค้าพร้อมสถานะ บันทึกย่อ และปุ่มลบที่ลบออกจริง
* คำสั่งที่คุณเขียนเอง เปลี่ยนได้จาก console โดยส่งเป็นข้อความหรือไฟล์ markdown และมี
  ปุ่มย้อนกลับเมื่อแก้แล้วผลออกมาแย่ลง
* รองรับธุรกิจกี่รายก็ได้ในการ deploy ครั้งเดียว โดยแต่ละรายแยกขาดจากกัน

## ก่อนเริ่มต้น

สี่อย่าง ฟรีทั้งหมด ใช้เวลาราวสิบนาที ไม่มีอย่างไหนขอบัตรชำระเงิน และคุณไม่ต้องเขียน
โค้ดเลยสักบรรทัด

### 1. บัญชี Cloudflare

นี่คือที่ที่ Muxel จะทำงาน และเป็นบัญชีที่จะเก็บเอกสารและบทสนทนาของคุณ สมัครได้ที่
[dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) แล้วยืนยันอีเมล
ที่ระบบส่งมาให้ ใช้แพ็กเกจฟรีต่อไปได้เลย Muxel ตั้งใจเลือกใช้เฉพาะบริการที่ไม่ต้องผูก
บัตร คุณจึงจะไม่ถูกถามหาบัตร

มีบัญชีอยู่แล้วใช่ไหม แค่ลงชื่อเข้าใช้แล้วไปขั้นถัดไปได้เลย

### 2. บัญชี GitHub

Cloudflare จะเก็บสำเนาของโค้ดนี้ไว้ในชื่อของคุณเอง เพื่อให้สร้างผู้ช่วยของคุณขึ้นใหม่ได้
ทุกครั้งที่คุณอัปเดต สมัครได้ที่ [github.com/signup](https://github.com/signup)

คุณไม่ต้องเขียนอะไรในนั้นเลย หลังติดตั้งเสร็จก็ปิดทิ้งและลืมมันไปได้ ยกเว้นการตั้งค่า
อย่างเดียวที่อธิบายไว้ด้านล่าง

### 3. bot Telegram สองตัว

เปิด [@BotFather](https://t.me/BotFather) ใน Telegram แล้วส่ง `/newbot` ทำสองครั้ง
เพราะ bot สองตัวนี้ทำหน้าที่ต่างกันและต้องไม่ใช่ตัวเดียวกันเด็ดขาด

| bot          | ใครเป็นคนทัก     | ตั้งชื่อประมาณนี้        |
| ------------ | ---------------- | ---------------------- |
| console bot  | คุณคนเดียว        | My Muxel Console       |
| business bot | ลูกค้าของคุณ      | ชื่อร้านของคุณ           |

ลูกค้าจะเห็นชื่อของ business bot ดังนั้นให้ตั้งชื่อตัวนั้นเป็นชื่อร้าน BotFather จะตอบทุกครั้ง
ที่คุณส่ง `/newbot` ด้วย token ยาว ๆ หน้าตาแบบ `8012345678:AAH...` เก็บทั้งสองอันไว้
ในที่ที่คุณคัดลอกมาใช้ได้

ตอน deploy คุณใช้แค่ token ของ console bot เท่านั้น ส่วน token ของ business bot จะถูก
ถามทีหลังใน console

### 4. ไอดีบัญชี Telegram ของคุณ

ส่ง `/start` ไปที่ [@userinfobot](https://t.me/userinfobot) แล้วมันจะตอบกลับมาเป็นตัวเลข
ซึ่งเป็นวิธีที่ console ใช้แยกคุณออกจากคนอื่นที่บังเอิญเจอ bot ของคุณ ไม่มีใครอื่นสั่งงานมันได้

## Deploy จากเบราว์เซอร์

กดปุ่มด้านล่าง หรือคัดลอกลิงก์นี้ไปวางในเบราว์เซอร์ของคุณ

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel)

```
https://deploy.workers.cloudflare.com/?url=https://github.com/thankywal/muxel
```

จากนั้น Cloudflare จะพาคุณผ่านสามขั้นตอนก่อนที่แบบฟอร์มจะปรากฏ ระบบจะขอให้คุณลงชื่อ
เข้าใช้ถ้ายังไม่ได้เข้า ขอเชื่อมต่อบัญชี GitHub ของคุณ และขอติดตั้งแอป GitHub ของ
Cloudflare ลงในบัญชีนั้น กรุณาอนุมัติ เพราะนี่คือวิธีที่ Cloudflare ใช้สร้างสำเนาโค้ดของคุณ
และสร้างใหม่ทุกครั้งที่คุณอัปเดต

ถ้าบัญชี GitHub ของคุณมีแอปชื่อ **Cloudflare Workers and Pages** ค้างอยู่จากโปรเจกต์เก่า
ให้ลบออกก่อนที่
[github.com/settings/installations](https://github.com/settings/installations)
แล้วปล่อยให้ขั้นตอนนี้ติดตั้งแอปตัวปัจจุบัน แอปตัวเก่าอาจคัดลอก repository ไม่ครบ
ซึ่งทำให้ deploy รายงานว่าสำเร็จแต่ไม่มีอะไรทำงาน ดูวิธีแก้ที่
[docs/DEPLOY-RECOVERY.md](docs/DEPLOY-RECOVERY.md)

ในแบบฟอร์ม ให้ยอมรับชื่อที่ระบบแนะนำสำหรับ KV namespace และฐานข้อมูล D1 แล้วกรอก
อีกสี่ช่อง

**Vectorize index จะขอค่าสองอย่างที่ระบบกรอกให้ล่วงหน้าไม่ได้** ค่าทั้งสองถูกกำหนด
ตายตัวตอนที่สร้าง index และไฟล์ตั้งค่าของ Worker ก็ไม่มีช่องสำหรับค่าเหล่านี้ ช่องกรอก
จึงมาถึงคุณแบบว่างเปล่า

| ช่องของ Vectorize | ค่า      |
| --------------- | -------- |
| Dimensions      | `1024`   |
| Metric          | `cosine` |

กรอกผิดไม่ใช่เรื่องร้ายแรงอีกต่อไป ระบบจะปรับ embedding ให้เข้ากับค่าที่ index ถูกสร้าง
ขึ้นมา และหน้า setup จะบอกคุณว่าผลที่ตามมาคืออะไร ถ้าใส่ตัวเลขมากเกินไป จะเปลืองพื้นที่
แต่ไม่เปลี่ยนอะไรเลย เพราะการเติมศูนย์เข้าไปทำให้ค่า cosine similarity เท่าเดิมทุกประการ
ถ้าใส่น้อยเกินไป ระบบจะตัด embedding ให้สั้นลงพอดีช่อง ทำให้การค้นหาแม่นยำน้อยลง
ซึ่งควรแก้ไข แต่ก็ไม่ได้ทำให้อะไรหยุดทำงาน

จากนั้นคือ secret สองตัว

| การตั้งค่า            | ค่า                                          |
| ------------------- | ------------------------------------------ |
| `ADMIN_BOT_TOKEN`   | token ของ console bot จาก BotFather         |
| `OWNER_TELEGRAM_ID` | ตัวเลขของคุณจาก @userinfobot ใส่เฉพาะตัวเลข     |

ส่วนที่เหลือระบบจัดการให้เองทั้งหมด รวมถึง webhook ของ Telegram ด้วย เพราะขั้นตอน
deploy จะยิงคำขอแรกไปที่ Worker เพื่อให้มันรู้ที่อยู่ของตัวเอง

เมื่อ build เสร็จ ให้เปิด console bot ของคุณแล้วส่ง `/start` bot ตัวนั้นคือแผงควบคุม
ส่วนตัวของคุณ เพิ่มธุรกิจในนั้นแล้วระบบจะถามหา bot ที่ลูกค้าจะทักเข้ามา

ถ้า bot เงียบไม่ตอบ ให้เปิดที่อยู่ Worker ที่ Cloudflare แสดงให้คุณเห็น หน้านั้นจะรัน setup
อีกครั้งและบอกว่ามีอะไรผิดพลาด

**ถ้าที่อยู่นั้นตอบว่า `Hello world` แสดงว่า deploy ยังไม่เสร็จ** Cloudflare จะคัดลอก
repository นี้เข้าบัญชี GitHub ของคุณก่อนจะ build และบางครั้งการคัดลอกนั้นล้มเหลวทั้งที่
dashboard ยังรายงานว่าสำเร็จ ผลคือไม่มีส่วนใดของ Muxel ทำงาน จึงไม่มีอะไรแจ้งปัญหานี้ให้คุณ
ทราบได้ [docs/DEPLOY-RECOVERY.md](docs/DEPLOY-RECOVERY.md) อธิบายวิธีตรวจสอบและวิธีติดตั้ง
ให้เสร็จสองแบบ ซึ่งแบบหนึ่งไม่ต้องใช้ GitHub เลย

ไม่ได้ถ้าไม่มีบัญชีของคุณ แต่ก็ไม่มีเหตุผลที่จะเปิดเผยต่อสาธารณะ ให้ตั้ง repository เป็น

หน้า setup จะตรวจสอบเรื่องนี้ให้คุณ และแสดงลิงก์ตรงไปยังการตั้งค่านั้นตราบใดที่สำเนา
ยังเป็นสาธารณะอยู่ พอคุณจัดการเรียบร้อย ข้อความแจ้งเตือนก็จะหายไปเอง คุณจึงไม่ต้องจำ
และไม่ต้องกดปิด Muxel ทำการเปลี่ยนแปลงนี้เองไม่ได้ เพราะ repository ถูกสร้างโดย
GitHub App ของ Cloudflare สำเนาที่ได้มาไม่มีโฟลเดอร์ `.github` ติดมาด้วย workflow

ไม่ควรถือด้วย

GitHub App ที่ติดตั้งไว้ ซึ่งถือสิทธิ์ `contents: write` บน repository ที่คุณอนุญาต และ
สิทธิ์การเข้าถึงของแอปที่ติดตั้งไว้ไม่ได้ขึ้นอยู่กับว่า repository เป็นสาธารณะหรือไม่

## การอัปเดตให้ทันสมัยอยู่เสมอ

การอัปเดต **ไม่** ทำงานอัตโนมัติ และควรอธิบายให้ชัดว่าเพราะอะไร

ปุ่ม deploy สร้างสำเนาที่เป็นอิสระ ไม่ใช่ fork ของ GitHub จึงไม่มีปุ่ม Sync fork และไม่มี
อะไรเชื่อมสำเนาของคุณกลับมาที่นี่ นอกจากนี้ยังคัดลอกโปรเจกต์ไป
**โดยไม่มีโฟลเดอร์ `.github`** เพราะการนำเข้าแบบนี้สร้างไฟล์ workflow ไม่ได้ ดังนั้น
workflow สำหรับอัปเดตที่มากับ repository นี้จึงไม่เคยไปถึงสำเนาของคุณ

สิ่งที่เกิดขึ้นเองโดยอัตโนมัติคือ ระบบที่คุณ deploy ไว้จะคอยตรวจสอบ repository นี้ว่ามี
เวอร์ชันใหม่หรือไม่ และจะ **ส่งข้อความหาคุณใน console bot** เมื่อมีเวอร์ชันใหม่ หนึ่งครั้ง
ต่อหนึ่งเวอร์ชัน คุณจึงไม่ต้องคอยจำว่าต้องเข้าไปดูเอง

### วิธีติดตั้งอัปเดต

```bash
git clone https://github.com/<you>/muxel.git && cd muxel
git remote add upstream https://github.com/thankywal/muxel.git

# every time, from here on
git fetch upstream
git checkout upstream/main -- .
git checkout HEAD -- wrangler.jsonc      # keeps your resource identifiers
git commit -am "Update from upstream" && git push
```

การ push จะไปกระตุ้น Workers Build ของคุณ ซึ่งจะ deploy ใหม่และทำ setup ให้เสร็จ
ข้อมูล การตั้งค่า และ bot ของคุณจะไม่ถูกแตะต้อง

### ทำให้อัปเดตอัตโนมัติ

ลงมือเองเพียงขั้นตอนเดียว แล้วหลังจากนั้นคุณจะได้อัปเดตอัตโนมัติทุกวัน ในสำเนาของคุณ
บน GitHub ให้เลือก **Add file** แล้วเลือก **Create new file** ตั้งชื่อไฟล์ว่า
`.github/workflows/update.yml` แล้ววาง
[workflow จาก repository นี้](.github/workflows/update.yml) ลงไป คุณสร้างไฟล์
workflow ด้วยมือได้ แม้ว่าการนำเข้าอัตโนมัติจะทำไม่ได้ก็ตาม

จากนั้นตรวจสอบที่ **Settings** ไป **Actions** ต่อด้วย **General** ว่า
**Workflow permissions** ถูกตั้งเป็น *Read and write* ไม่อย่างนั้นงานนี้จะ push เข้า
repository ของคุณเองไม่ได้

ระบบจะติดตั้งอัปเดตก็ต่อเมื่อ commit ต้นทางผ่านการทดสอบของตัวเองแล้ว commit ที่เสีย

## bot สองแบบ

ความแตกต่างนี้สำคัญมาก และ console ถูกออกแบบขึ้นมารอบ ๆ เรื่องนี้

| | console bot | business bot |
| --- | --- | --- |
| ใครเป็นคนทัก | คุณคนเดียว | ลูกค้าของคุณ |
| เข้าถึงอะไรได้บ้าง | ทุกธุรกิจ | ธุรกิจเดียวเท่านั้น |
| มาจากไหน | `ADMIN_BOT_TOKEN` ตอน deploy | สร้างขึ้นต่อหนึ่งธุรกิจใน console |
| สังกัดธุรกิจหรือไม่ | ไม่เคย | ใช่ ธุรกิจที่มันให้บริการอยู่ |

ธุรกิจหนึ่งมีอยู่ได้เพราะมี bot คอยให้บริการ ทั้งสองอย่างจึงถูกสร้างขึ้นพร้อมกัน เมนู
เพิ่มธุรกิจจะถามหา token ของ bot แทนที่จะถามชื่อ และชื่อของ bot จะกลายเป็นชื่อธุรกิจ
ไปเอง ไม่มีขั้นตอนไหนที่ธุรกิจต้องนั่งรอ bot และไม่มีทางผูก console bot เข้ากับธุรกิจได้
เพราะ console จะปฏิเสธ token ของตัวเอง

## console

ทุกอย่างหลังการติดตั้งเกิดขึ้นใน console bot ด้วยการกดปุ่มทั้งหมด

| หน้าจอ | มีอะไรอยู่ในนั้น |
| --- | --- |
| Data | ไฟล์ที่อัปโหลดไว้ แถวละหนึ่งไฟล์ พร้อมปุ่มลบทุกแถว |
| Products | สินค้าที่พิมพ์เพิ่มทีละรายการ หรืออัปโหลดเข้ามาทีเดียวหลายรายการ |
| Customers | ทุกคนที่เคยทักเข้ามา พร้อมสถานะ บันทึกย่อ และความจำ |
| Instructions | กฎของคุณเองสำหรับผู้ช่วย พร้อมปุ่มย้อนกลับ |
| Bots | business bot ที่ลูกค้าทักเข้ามา และปุ่มสำหรับเพิ่มตัวใหม่ |

หน้า Data รับไฟล์ PDF, Word, Excel, CSV, TXT, Markdown, JSON และ JSONL ไฟล์ที่
เป็นข้อความล้วนจะถูกอ่านตรง ๆ ส่วนสเปรดชีตและเอกสารจะผ่านตัวแปลงของแพลตฟอร์ม
และถ้ามี PDF ที่อ่านไม่ออก ระบบจะลองใหม่โดยอ่านจากชั้นข้อความแทน ซึ่งเป็นสิ่งที่ทำให้
รายการราคาที่ส่งออกมาจาก Excel ใช้งานได้

ไฟล์ทุกไฟล์ต้องสังกัดธุรกิจใดธุรกิจหนึ่ง console จึงขอให้คุณเปิดธุรกิจนั้นก่อนที่จะรับไฟล์
อัปโหลด แทนที่จะเดาเอาเอง

หน้า Products มีอยู่คู่กับไฟล์ เพราะไฟล์หนึ่งไฟล์แทนที่ได้ทั้งไฟล์เท่านั้น ราคาที่เปลี่ยนไป
เพียงรายการเดียวไม่ควรทำให้คุณต้องอัปโหลดแคตตาล็อกใหม่ทั้งเล่ม สินค้าถูกกรอกใน
รูปแบบ `name | price | description` บรรทัดละหนึ่งรายการ จะพิมพ์เองหรืออัปโหลดก็ได้
และลบออกได้ทีละรายการ ทุกการเปลี่ยนแปลงจะสร้างความรู้ของผู้ช่วยขึ้นใหม่

การลบธุรกิจจะขอให้คุณยืนยันก่อน แล้วจึงลบไฟล์ สินค้า ลูกค้า bot และ vector ของธุรกิจนั้น
ออกไปพร้อมกันทั้งหมด

### ภาษา

console รองรับภาษา English, ไทย, 中文 และ မြန်မာ ภาษาเป็นค่าเฉพาะของผู้ใช้แต่ละคน
และเปลี่ยนทุกปุ่ม ไม่ใช่แค่หน้าจอถัดไป ทั้งนี้แยกต่างหากจากภาษาที่ธุรกิจใช้ตอบลูกค้า

## เมื่อผู้ช่วยไม่ควรตอบ

ผู้ช่วยตอบจากเอกสารที่คุณให้ไว้ คำถามบางอย่างไม่มีอยู่ในเอกสาร เช่น ส่วนลดที่ไม่มีใคร
จดไว้ คำร้องเรียน หรือการสั่งทำพิเศษ การเดาคำตอบในเรื่องพวกนี้คือความผิดพลาดที่ทำให้
เสียลูกค้า ผู้ช่วยจึงไม่เดา

แทนที่จะเดา ผู้ช่วยจะบอกลูกค้าว่าจะมีคนติดต่อกลับ และแจ้งคุณด้วย การแจ้งเตือนจะมาถึง
ใน console พร้อมปุ่มที่เปิดบทสนทนานั้นได้ทันที

จากหน้าจอของลูกค้าใน console

| สิ่งที่กด                        | ผลที่เกิดขึ้น                                              |
| ----------------------------- | ------------------------------------------------------- |
| **Conversation**              | บทสนทนาทั้งหมด พร้อมระบุว่าใครเป็นคนพูดแต่ละบรรทัด            |
| **Take over**                 | ผู้ช่วยจะเงียบไปในแชทนั้น                                    |
| **Send a message**            | คุณพิมพ์เอง แล้วลูกค้าจะได้รับข้อความนั้นจาก business bot        |
| **Give back to the assistant**| ผู้ช่วยกลับมาตอบต่อ                                        |

ระหว่างที่คุณตอบเอง ผู้ช่วยจะหลบให้และส่งต่อทุกอย่างที่ลูกค้าพิมพ์มาให้คุณ จึงไม่มีทางที่
สองเสียงจะตอบคนเดียวกันพร้อมกัน ข้อความที่คุณส่งจะถูกบันทึกเป็นส่วนหนึ่งของบทสนทนา
ด้วย นั่นแปลว่าผู้ช่วยได้อ่านมันแล้วถ้าคุณคืนแชทให้มันดูแลต่อ

เมนู **Waiting for a person** บนหน้าแรกของ console จะแสดงทุกแชทที่รอคุณอยู่
ครอบคลุมทุกธุรกิจของคุณ

คำถามที่ผู้ช่วยตอบไม่ได้ ไม่ได้ทำให้มันเงียบไปตลอดทั้งแชท มันยังตอบเรื่องอื่น ๆ ต่อไป
เพราะการเงียบหายไปเพราะคำถามยากเพียงข้อเดียวย่อมแย่กว่าตัวคำถามเสียอีก

## คำสั่งกับเอกสารเป็นคนละเรื่องกัน

console แยกสองอย่างนี้ออกจากกัน เพราะผู้ช่วยต้องให้ความเชื่อถือกับมันไม่เท่ากัน

| | คำสั่ง | เอกสาร |
| --- | --- | --- |
| ใครเป็นคนเขียน | คุณ | คุณ แต่บ่อยครั้งได้มาจากซัพพลายเออร์หรือลูกค้า |
| ระบบปฏิบัติกับมันอย่างไร | เป็นกฎที่ผู้ช่วยต้องทำตาม | เป็นข้อเท็จจริงที่ผู้ช่วยยกมาอ้างได้ |
| ถูกนำไปไว้ที่ไหน | ใน system prompt | อยู่ในเครื่องหมายคั่นแบบข้อความอ้างอิง |

คำสั่งคือข้อความของคุณเอง จึงใช้กำหนดน้ำเสียงและนโยบายได้ ส่วนเอกสารคือข้อมูลนำเข้า
ที่ยังไว้ใจไม่ได้ ผู้ช่วยจึงถูกบอกไว้ล่วงหน้าให้อ่านมันในฐานะข้อมูลเท่านั้น ประโยคที่อยู่ใน
ไฟล์ PDF จึงเปลี่ยนพฤติกรรมของผู้ช่วยไม่ได้ และกฎที่ห้ามแต่งราคาขึ้นเองก็ยังอยู่ ไม่ว่า
คำสั่งของคุณจะเขียนไว้ว่าอย่างไร

ส่งเอกสารเข้า console เมื่อไรก็ได้ แล้วมันจะเข้าไปรวมกับความรู้ของธุรกิจที่คุณเปิดไว้
ล่าสุด ส่วนคำสั่งต้องเปลี่ยนอย่างชัดเจนจากหน้า Instructions โดยส่งเป็นข้อความหรือ
ไฟล์ `.md` และเวอร์ชันก่อนหน้าจะถูกเก็บไว้ เผื่อว่าแก้แล้วผลไม่ดีจะได้ย้อนกลับได้

## ความจำ

ข้อเท็จจริงเกี่ยวกับลูกค้าจะถูกสกัดออกมาจากบทสนทนาทุก ๆ ไม่กี่ข้อความ แล้วเก็บไว้กับ
ประวัติของลูกค้าคนนั้น ลูกค้าที่กลับมาอีกครั้งจึงไม่ต้องบอกซ้ำว่าเคยซื้ออะไรหรือจ่ายเงิน
ด้วยวิธีไหน

ข้อเท็จจริงเหล่านี้อยู่ใน D1 และถูกดึงมาด้วย key แทนที่จะทำ embedding แล้วค้นหา คน
หนึ่งคนสะสมข้อเท็จจริงได้ระดับหลักสิบ ไม่ใช่หลักพัน การค้นด้วย index เพียงครั้งเดียวจึง
ได้มาครบทั้งหมด แบบนี้ทำให้โควตา Vectorize ทั้งก้อนเหลือไว้ให้เอกสาร ซึ่งเป็นงานที่การ
ค้นแบบเข้าใจความหมายคุ้มค่ากับต้นทุน

หน้าจอลูกค้าจะแสดงสิ่งที่ระบบจำไว้ และมีทั้งตัวเลือกให้ลืมข้อเท็จจริงเหล่านั้น และลบลูกค้า
คนนั้นออกไปทั้งหมด

## การเปลี่ยน console bot

ใน console ให้เปิดหน้า Bots แล้วเลือก Replace console bot จากนั้นส่ง token ตัวใหม่
เข้าไป ระบบจะปลด bot ตัวเก่าออกก่อน ทั้งสองตัวจึงไม่มีทางตอบพร้อมกัน แล้ว bot ตัวใหม่
จะยืนยันกลับมาในแชทเดียวกัน

ถ้าคุณเข้า console ไม่ได้เลย ให้เปลี่ยน secret ชื่อ `ADMIN_BOT_TOKEN` ใน dashboard
ของ Cloudflare แล้วเข้าไปที่ `/setup` อีกครั้ง เส้นทางนี้จะเขียนข้อมูลรับรองที่เก็บไว้ใหม่
พร้อมกับ webhook ด้วย

## ค่าใช้จ่ายในการใช้งาน

Muxel ไม่คิดเงินคุณเลย และร้านเล็ก ๆ ร้านหนึ่งก็ใช้งานได้พอดีในแพ็กเกจฟรีของ Cloudflare

| ทรัพยากร     | โควตาฟรี                                | หมายความว่าอย่างไรในที่นี้           |
| ---------- | ------------------------------------- | --------------------------------- |
| Workers AI | 10,000 neuron ต่อวัน                    | ราว 330 คำตอบต่อวันเมื่อใช้ Gemma 4  |
| Vectorize  | เก็บ 5 M และค้นหา 30 M dimension          | เอกสารราว 4,800 ชิ้นส่วน            |
| D1         | 5 GB และเขียน 100 k แถวต่อวัน              | เกินกว่าที่ร้านหนึ่งร้านจะสร้างได้มาก   |
| Workers    | 100,000 request ต่อวัน                  | เกินกว่าที่ร้านหนึ่งร้านจะสร้างได้มาก   |

ที่ 1,024 dimension ต่อหนึ่ง vector โควตาพื้นที่เก็บของ Vectorize คิดออกมาได้ราว 4,800
ชิ้นส่วน ซึ่งอยู่ในระดับหนึ่งพันหน้าของรายการราคาและนโยบาย

ถ้าใช้เกินโควตาการประมวลผล ค่าใช้จ่ายอยู่ที่ 0.011 USD ต่อ 1,000 neuron ก้าวแรกที่พ้น
จากของฟรีจึงเป็นเรื่องของเศษเซ็นต์ ไม่ใช่การเปลี่ยนแพ็กเกจ มีเพียงการเลือก model จาก
ผู้ให้บริการรายอื่นเท่านั้นที่ต้องจ่ายเงินล่วงหน้า เพราะคุณจ่ายให้ผู้ให้บริการรายนั้นโดยตรง

### การดูปริมาณที่คุณใช้ไปแล้ว

console มีหน้าจอ **Usage** อยู่ โดยไม่ต้องตั้งค่าอะไรเลย หน้านี้จะรายงานว่าระบบที่คุณ
deploy ไว้ตอบไปกี่ครั้งในวันนี้ และใช้ token ไปเท่าไร เพราะ Muxel นับตัวเลขเหล่านี้เอง

ยอดรวมทั้งบัญชีเป็นอีกเรื่องหนึ่ง เพราะ Worker ตัวอื่นของคุณก็ดึงจากโควตาก้อนเดียวกัน
และมีแต่ Cloudflare เท่านั้นที่ตอบได้ ถ้าอยากให้แสดงยอดรวมนี้ ให้สร้าง API token ที่มี
สิทธิ์ **Account Analytics: Read** เพียงอย่างเดียว แล้วเพิ่ม secret สองตัวให้ Worker ที่
Settings แล้วไป Variables and Secrets

| Secret          | ค่า                                        |
| --------------- | ---------------------------------------- |
| `CF_ACCOUNT_ID` | id บัญชีของคุณ ดูได้จาก URL ของ dashboard     |
| `CF_API_TOKEN`  | token แบบอ่านอย่างเดียวที่คุณเพิ่งสร้าง          |

จากนั้นหน้าจอนี้จะแสดงจำนวน neuron ที่ใช้ไปวันนี้เทียบกับโควตารายวัน แยกรายละเอียด
ตาม model จำนวน request ของ Worker การค้นหาและพื้นที่เก็บของ Vectorize และการ
ประมาณว่าโควตาที่เหลือของวันนี้ยังตอบได้อีกกี่ครั้ง ตัวเลขประมาณนั้นคำนวณจากต้นทุน
จริงของคำตอบของคุณเอง ไม่ใช่จากอัตราที่ประกาศไว้ มันจึงยังแม่นยำอยู่แม้คุณจะเปลี่ยน model

token นี้อ่านได้อย่างเดียว มันสั่ง deploy ไม่ได้ เปลี่ยนการตั้งค่าไม่ได้ และอ่านข้อมูลของคุณ
ไม่ได้ ทั้ง Muxel ก็ไม่เคยแสดงมันออกมาให้เห็น

Muxel ตั้งใจไม่ใช้ R2 bucket เลย เพราะมันมีไว้เพียงเพื่อเก็บไฟล์ต้นฉบับที่อัปโหลดเข้ามา
ซึ่งไม่มีส่วนไหนอ่านกลับไปใช้ และการเปิดใช้ R2 ต้องผูกวิธีชำระเงินไว้ แม้จะอยู่ในโควตาฟรี
ของมันเองก็ตาม ถ้าคุณอยากเก็บไฟล์ต้นฉบับไว้ ให้เพิ่ม binding ชื่อ `DOCUMENTS` เข้าไป

## ความปลอดภัย

* ข้อมูลธุรกิจไม่เคยออกไปนอกบัญชี Cloudflare ของคุณ และไม่เคยเข้าไปอยู่ใน
  repository เพราะ Worker ไม่มีช่องทางเขียนลง git
* token ของ bot ถูกเข้ารหัสปิดผนึกด้วย AES-GCM ก่อนไปถึงฐานข้อมูล การส่งออก
  ฐานข้อมูลออกมาเฉย ๆ จึงไม่ได้ข้อมูลรับรองที่ใช้งานได้
* token ของ bot ที่คุณวางลงใน console จะถูกลบออกจากแชททันที
* webhook ถูกตรวจสอบสิทธิ์ด้วย secret เฉพาะของแต่ละ bot โดยใช้การเปรียบเทียบที่
  ใช้เวลาคงที่ เส้นทางที่ไม่รู้จักและ secret ที่ผิดจะได้ 404 เหมือนกันทั้งคู่ จึงไม่มีใคร
  สุ่มหา endpoint ที่ใช้ได้จริงจากระบบของคุณได้
* เส้นทางการตอบไม่เปิดเครื่องมือใด ๆ ให้เรียกใช้ เอกสารที่ค้นมาได้จะถูกคั่นขอบเขตและ
  กำกับไว้ว่าเป็นข้อมูลอ้างอิง ข้อความในไฟล์ที่อัปโหลดเข้ามาจึงสั่งเปลี่ยนทิศทางของ
  ผู้ช่วยไม่ได้
* ทุกคำสั่งค้นข้อมูลที่แตะเนื้อหาของธุรกิจ จะกรองด้วยรหัสธุรกิจที่ชั้นข้อมูล ไม่ใช่ที่ตัว
  จัดการคำขอ

แจ้งช่องโหว่ด้านความปลอดภัยได้ที่ [SECURITY.md](SECURITY.md)

## สถานะของโครงการ

เวอร์ชัน 0.1 มุ่งเป้าไปที่ Cloudflare และ Telegram ส่วนของ callback codec การตัดแบ่ง
ข้อความ การปิดผนึกข้อมูลรับรอง ตัวแยกวิเคราะห์การสกัดความจำ และกระบวนการค้นคืน
เอกสาร ล้วนมีการทดสอบครอบคลุมแล้ว และกระบวนการค้นคืนก็ถูกรันทดสอบตั้งแต่ต้นจนจบ
กับบัญชีจริงมาแล้ว ส่วน console ยังไม่ได้ถูกทดสอบกับ bot ที่ deploy จริง
